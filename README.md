# Ростовводоканал для Home Assistant

[![Проверки](https://github.com/NyrouxHide/hass-rostov-vodokanal/actions/workflows/ci.yaml/badge.svg)](https://github.com/NyrouxHide/hass-rostov-vodokanal/actions)
[![HACS / Marketplace](https://img.shields.io/badge/HACS-custom-orange.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=NyrouxHide&repository=hass-rostov-vodokanal&category=integration)
[![Home Assistant](https://img.shields.io/badge/Home%20Assistant-2026.3%2B-blue.svg)](https://www.home-assistant.io/)
[![Лицензия MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Независимая интеграция с личным кабинетом **АО «Ростовводоканал»**:
последние показания, дата передачи, задолженность, пени, поверка, отправка
и отмена показаний. Домен интеграции — `rostov_vodokanal`.

Это общественный проект, использующий формы сайта
[lkfl.vodokanalrnd.ru](https://lkfl.vodokanalrnd.ru), а не официальный API
или продукт Водоканала. Подключение само по себе только читает данные.
Расписание передачи пользователь задаёт отдельной автоматизацией.

## Почему не нужны логин и пароль

На сайте Водоканала есть публичные формы «Передать показания» и «Оплатить»
**без регистрации**. В них достаточно указать лицевой счёт. Интеграция
использует эти же формы, их CSRF-токены и отдельную cookie-сессию для каждого
счёта. Она не входит в учётную запись, не подбирает пароль и не создаёт платёж.

По лицевому счёту сайт отдаёт последние показания и их дату, следующую поверку,
сумму по услугам и пени. Поэтому пароль не запрашивается и не хранится.
Сам лицевой счёт при этом стоит считать личными данными: он открывает
доступ к этим публичным формам. Диагностика интеграции скрывает счёт,
адрес и идентификаторы приборов и записей.

Изменение сайта может потребовать обновления интеграции. Если данные
не распознаны, она сообщает об ошибке, а не подставляет нулевую задолженность.

## Установка через Marketplace — Home Assistant 2026.11 и новее

В Home Assistant 2026.11 HACS стал встроенным **Marketplace**. Отдельно
устанавливать HACS на этих версиях не нужно.

[![Открыть HACS / Marketplace](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=NyrouxHide&repository=hass-rostov-vodokanal&category=integration)

1. Откройте **Настройки → Marketplace → Добавить по ссылке**.
2. Укажите `https://github.com/NyrouxHide/hass-rostov-vodokanal`.
3. Если потребуется выбрать тип, выберите **Интеграция**.
4. Откройте добавленный репозиторий и нажмите **Установить**.
5. Выполните перезапуск Home Assistant, если Marketplace об этом попросит.
6. Откройте **Настройки → Устройства и службы → Добавить интеграцию → Ростовводоканал**.
7. Укажите номер лицевого счёта. Пароль не нужен.

Для добавления пользовательского репозитория Marketplace может попросить
подключить GitHub. Это доступ магазина к публичным репозиториям GitHub;
к авторизации в Водоканале он отношения не имеет.

## Установка через HACS — Home Assistant 2026.3–2026.10

1. Установите и настройте [HACS по его инструкции](https://hacs.xyz/docs/use/).
2. В HACS откройте меню **⋮ → Пользовательские репозитории**.
3. Добавьте `https://github.com/NyrouxHide/hass-rostov-vodokanal`, тип **Интеграция**.
4. Найдите **Ростовводоканал**, скачайте и перезапустите Home Assistant.
5. Добавьте интеграцию через **Настройки → Устройства и службы** и укажите лицевой счёт.

Минимальная версия Home Assistant — **2026.3**. Для ручной установки скопируйте
`custom_components/rostov_vodokanal` в каталог `custom_components` вашей конфигурации
и перезапустите Home Assistant. Marketplace/HACS удобнее для дальнейших обновлений.

Если интеграция уже была установлена вручную, устанавливайте репозиторий
поверх того же домена. Существующая запись интеграции и идентификаторы сущностей
сохраняются. Другая интеграция с доменом `vodokanal` от этого не меняется.

## Что появляется в Home Assistant

Для лицевого счёта создаётся устройство:

| Сущность | Что показывает |
| --- | --- |
| Задолженность по услугам | Сумму по услугам из платёжной проверки сайта, без опции будущих начислений |
| Пени | Отдельную сумму пеней |
| Всего к оплате | Задолженность по услугам плюс пени |
| Платёжный период | Период, который возвращает сайт |
| Последнее обновление | Время последнего успешного чтения кабинета |
| Обновить данные | Кнопку ручного обновления |

Для каждого прибора и тарифа создаётся связанное устройство:

| Сущность | Что показывает |
| --- | --- |
| Последнее переданное показание | Значение из кабинета, м³ |
| Дата последней передачи | Дату последней записи на сайте |
| Следующая поверка | Дату из формы прибора |
| Передача показаний доступна | Можно ли сейчас передавать показания по данным формы и дате записи |
| Отмена показания доступна | Есть ли запись и доступная форма её отмены |

Датчики счётчика имеют атрибуты `meter_id`, `reading_id`, `meter_number`,
`service`, `tariff`. `meter_id` обозначает прибор и тариф, а `reading_id` —
конкретную переданную запись. После новой передачи `reading_id` меняется.

Дата передачи берётся с сайта. Она не заменяется датой запуска Home Assistant
и не получает выдуманное время суток. После отмены показание и дата возвращаются
к предыдущей записи. Это данные кабинета, а не непрерывная телеметрия расхода;
поэтому датчик показаний не объявлен статистическим счётчиком потребления.

По умолчанию чтение выполняется раз в **6 часов**. В параметрах интеграции можно
выбрать интервал **15–1440 минут**. Перед каждой отправкой или отменой кабинет
перечитывается заново, независимо от периода обновления.

## Однократная передача и проверка результата

За день передаётся одно показание каждого счётчика/тарифа. Интеграция проверяет
дату последней записи и доступность поля на сайте. Если показание уже передано
сегодня или сайт заблокировал форму, повторный записывающий запрос не выполняется.
Используется дата Ростова — **Europe/Moscow**, а не часовой пояс сервера HA.
Окончательные ограничения всегда определяет Водоканал.

Новая цифра должна быть неотрицательной и не меньше предыдущей. Нулевой расход
допустим: можно передать то же значение, но успехом считается только **новая запись**
с сегодняшней датой и новым `reading_id`. Поддерживаются до трёх знаков после
запятой и значения до 99 999 999 м³.

Допустимый расход берётся из формы прибора. В текущей анонимной форме для холодной
воды проверка сайта запрещает расход **от 100 м³**, для горячей — **от 50 м³**.
Интеграция соблюдает фактическую проверку формы, даже если текстовая подсказка сайта
формулирует границу иначе. Для больших объёмов сайт предлагает авторизованный кабинет.

Отправляется только выбранный прибор. Запросы одного лицевого счёта выполняются
последовательно. Ответ HTTP 200 или зелёный баннер сами по себе не означают успех:
интеграция повторно читает кабинет и сверяет значение, дату и новый идентификатор.

При таймауте ответ мог потеряться **после принятия показаний**. Поэтому записывающие
запросы не повторяются автоматически. Неопределённый результат возвращается как
ошибка с `outcome: unknown`: сначала обновите данные и посмотрите запись на сайте.
Событие успешной отправки в такой ситуации не публикуется.

## Действия

Действия доступны в **Инструменты разработчика → Действия**. Выберите подключённый
лицевой счёт в поле интеграции. Если счётчик один, `meter_id` можно не указывать.

| Действие | Обязательные поля | Назначение |
| --- | --- | --- |
| `rostov_vodokanal.refresh` | `config_entry_id` | Заново прочитать данные |
| `rostov_vodokanal.send_reading` | `config_entry_id`, `value` | Передать показание |
| `rostov_vodokanal.cancel_reading` | `config_entry_id`, `reading_id` | Отменить именно выбранную запись |

`meter_id` — необязательное дополнительное поле отправки и отмены.
`value` принимает число или числовую строку, в том числе результат шаблона.
Оба разделителя дробной части поддерживаются: `123.456` и `123,456`.

Необязательный `response_variable` позволяет получить ответ:
`success`, `meter_id`, `reading`, `date`, `reading_id`. При ошибке действие
завершается исключением, а не возвращает ложный результат «успешно».

## Пример: отправка показаний и отдельное уведомление в Telegram

Это две независимые автоматизации, как в интеграциях с событиями завершения.
Первая отправляет показания. Вторая уведомляет **только после подтверждения кабинетом**,
в том числе при ручной отправке через действие интеграции.

Замените `YOUR_CONFIG_ENTRY_ID` в обоих примерах, `counter.water_reading` на свой
источник показаний и `notify.telegram_me` на свою сущность уведомления Telegram.
Идентификатор записи интеграции проще получить, выбрав лицевой счёт в действии
`rostov_vodokanal.send_reading` через интерфейс и переключившись на YAML.

### 1. Передача 25-го числа в 12:00

```yaml
- id: rostov_vodokanal_monthly_reading
  alias: Ростовводоканал — передача показаний
  triggers:
    - trigger: time
      at: "12:00:00"
  conditions:
    - condition: template
      value_template: "{{ now().day == 25 }}"
    - condition: template
      value_template: "{{ is_number(states('counter.water_reading')) }}"
  actions:
    - action: rostov_vodokanal.send_reading
      data:
        config_entry_id: YOUR_CONFIG_ENTRY_ID
        value: "{{ states('counter.water_reading') }}"
  mode: single
```

25-е число — пример. Выберите нужный день по правилам своего лицевого счёта.
Значение источника должно быть фактическим показанием прибора. Недоступный датчик
не превращается в ноль: условие `is_number` пропускает только числовое значение.

### 2. Telegram после события успешной передачи

```yaml
- id: rostov_vodokanal_reading_sent_notification
  alias: Ростовводоканал — уведомление об отправке
  triggers:
    - trigger: event
      event_type: rostov_vodokanal_send_reading_completed
      event_data:
        config_entry_id: YOUR_CONFIG_ENTRY_ID
  actions:
    - action: notify.send_message
      target:
        entity_id: notify.telegram_me
      data:
        title: "Ростовводоканал: показания переданы"
        message: >-
          Счётчик №{{ trigger.event.data.meter_number }}.
          Показание: {{ trigger.event.data.reading }} м³.
          Дата в кабинете: {{ trigger.event.data.date }}.
  mode: queued
```

Дополнительный вызов уведомления после `send_reading` не нужен: событие уже
приходит для каждой подтверждённой передачи, независимо от места запуска.
Автоматизации-примеры не устанавливаются и не включаются автоматически.

## События

| Событие | Когда публикуется |
| --- | --- |
| `rostov_vodokanal_send_reading_completed` | Новая запись подтверждена в кабинете |
| `rostov_vodokanal_send_reading_failed` | Действие отклонено, недоступно или результат не подтверждён |
| `rostov_vodokanal_cancel_reading_completed` | Подтверждено исчезновение отменяемой записи |
| `rostov_vodokanal_cancel_reading_failed` | Отмена не выполнена или её результат не подтверждён |
| `rostov_vodokanal_refresh_completed` | Ручное действие обновления выполнено |
| `rostov_vodokanal_refresh_failed` | Ручное действие обновления завершилось ошибкой |

Плановое фоновое чтение и кнопка обновления не являются отправкой показаний.
Успешное событие отправки содержит:

```yaml
config_entry_id: YOUR_CONFIG_ENTRY_ID
success: true
account: "123456789"
device_id: HA_METER_DEVICE_ID
meter_id: "123456_0"
meter_number: "76543210"
service: Холодное водоснабжение
tariff: "0"
reading: "123.456"
date: "2026-11-08"
reading_id: "987654321"
timestamp: "2026-11-08T09:00:00+00:00"
```

`date` — дата записи сайта, `timestamp` — время подтверждения операции в UTC.
Событие наследует контекст вызова действия, поэтому связано с его трассировкой.
Отмена дополнительно содержит `cancelled_reading_id`; `reading_id`, `reading`
и `date` после отмены описывают восстановленную предыдущую запись.

Событие ошибки содержит `config_entry_id`, необязательный `meter_id`,
`error_code` и `outcome`. При неопределённом результате —
`error_code: mutation_uncertain`, `outcome: unknown`. Это не означает, что
сайт точно не принял показания. HTML, cookies и CSRF в события не попадают.

## Отмена ошибочного показания

Для отмены нужны `reading_id` конкретной записи и, при нескольких приборах,
`meter_id`. Они доступны в атрибутах датчика последнего показания.

```yaml
action: rostov_vodokanal.cancel_reading
data:
  config_entry_id: YOUR_CONFIG_ENTRY_ID
  meter_id: "123456_0"
  reading_id: "987654321"
```

Перед отменой запись перечитывается. Если её идентификатор уже изменился,
операция отклоняется: устаревшая команда не может удалить более новое показание.
После отмены данные снова читаются и проверяется исчезновение нужной записи.
Возможность новой передачи в тот же день определяется текущей формой и сервером.

## Совместимость и диагностика

Интеграция использует проверку SSL-сертификата, не записывает пароли и не требует
внешнего адреса Home Assistant. Несколько лицевых счетов имеют независимые сессии.
Существующую интеграцию `vodokanal` и её автоматизации можно оставить; переход на
новые действия выполняется отдельно. Не назначайте обеим интеграциям передачу
одного счётчика на один и тот же день.

Диагностика доступна в меню записи интеграции. При обращении в
[Issues](https://github.com/NyrouxHide/hass-rostov-vodokanal/issues) укажите версию
Home Assistant и интеграции, описание действия и обезличенный текст ошибки.
Лицевой счёт, адрес, cookies и CSRF публиковать не нужно.

## Разработка и проверки

```sh
python -m pip install "homeassistant==2026.11.0" -r requirements-test.txt
python -m pytest
ruff check .
ruff format --check .
```

Автотесты используют локальный имитатор и обезличенные формы. Они проверяют чтение,
отправку, отмену, дневной лимит, одновременные обращения, сбои после принятия записи,
валидацию форм, события завершения и сокрытие данных в диагностике. Автотесты
не отправляют реальные показания. Реальный цикл «передача → проверка → отмена»
дополнительно проверен владельцем на своём лицевом счёте.
